# Озвучка YouTube на iPhone через свой Gemini-ключ

Экспериментальная версия **0.1.3** для **Safari + Userscripts**. Это отдельный
скрипт, расширение Chrome 0.5.0 не меняется.

Скрипт переводит **существующие субтитры** и воспроизводит **русскую речь Gemini TTS**.
Звук вкладки не захватывается. Если у ролика нет доступных субтитров, нужен файл
SRT/VTT/JSON3 с тайм-кодами. Универсального перевода любого видео здесь пока нет.

## Установка с телефона

1. Установи [Userscripts из App Store](https://apps.apple.com/app/userscripts/id1463298887).
2. Открой Userscripts и выбери папку для скриптов в «Файлах» (если приложение её просит).
3. В настройках iPhone: **Приложения → Safari → Расширения → Userscripts**
   включи расширение. Разреши доступ к `youtube.com`; при запросе отдельно разреши
   запросы к `generativelanguage.googleapis.com`.
4. Открой установочную ссылку на **`youtube-gemini-voice.user.js`** в Safari.
   Открой меню расширений Safari → **Userscripts** → **Install**.
   Если диалог не появился: сохрани `.user.js` в папку из шага 2 через «Файлы».
   Проверь, что имя заканчивается `.user.js`, а не `.txt`.
5. Открой ролик на **youtube.com в Safari**, не в приложении YouTube.
   Обнови страницу. Справа внизу появится **«Gemini · озвучка YouTube»**.

Официальная инструкция Userscripts: <https://github.com/quoid/userscripts#usage>.
Меню iOS могут немного отличаться в зависимости от версии системы.

## Первый тест

Если запросы субтитров пустые, открой описание ролика и нажми **«Показать текст
видео» / Show transcript**. Должен появиться список фраз с тайм-кодами. В панели
скрипта нажми **«Взять открытую расшифровку YouTube»**. Он прочитает текст из
страницы без запросов к `timedtext`. Если YouTube загрузил только часть списка,
озвучиваться будет эта часть; на её конце видео остановится. Прокрути расшифровку
для подгрузки и прочитай её заново. После перехода на другой ролик данные очищаются.

1. Один раз запусти оригинальный ролик, затем поставь его на паузу возле речи.
2. Вставь Gemini API key **в поле скрипта на телефоне**. Не присылай ключ в чат.
   По умолчанию он не сохраняется на диск. Сохранение включается отдельной галочкой;
   это хранилище расширения, не системная связка ключей. «Забыть ключ» удаляет запись.
3. Нажми **Проверить ключ**. Успех означает доступ к списку моделей, но не гарантирует
   доступ к TTS. В «Модели и голос» можно выбрать доступные модели из списков или
   вписать их имена вручную. По умолчанию: `gemini-3.8-flash` для текста и
   `gemini-3.8-flash-tts` для голоса. Для старых TTS-моделей используется прежний
   формат `prebuiltVoiceConfig`; для 3.8 — `voice`.
4. Нажми **Тест 60 секунд**. После подготовки первого фрагмента нажми **Продолжить ▶**.
5. Проверь: слышен русский голос; пауза останавливает его; перемотка меняет фрагмент;
   **Стоп** останавливает звук и отменяет незавершённые запросы.

Тест переводит ближайшие блоки от текущей позиции до лимита в 60 секунд и готовит
один блок вперёд. При запуске посередине блока переводится весь блок. Последний
блок может выходить за границу минуты, но воспроизведение остановится на границе.
Запросы уже принятые Google могут учитываться в квотах даже после отмены.

**Это два отдельных вызова Gemini на блок**: перевод текста и генерация речи.
Квоты и оплата зависят от моделей и Google-проекта. Подписка приложения Gemini
не заменяет API-доступ. При HTTP 429 скрипт останавливается без автоматических повторов.

## Что проверено и что ещё нет

Проверки облачного Chromium используют имитацию YouTube и Gemini, настоящий
AudioContext и тестовый PCM. Они не подтверждают доступность моделей твоему ключу,
живую выдачу субтитров YouTube или поведение Safari на настоящем iPhone.
Ключа в облаке нет, реальные платные запросы не выполнялись.

Для отчёта об ошибке скопируй **«Диагностика без ключа»** и текст статуса.
Не отправляй сам ключ, содержимое поля ключа или приватные субтитры.

## Ограничения

- Обычные страницы `/watch?v=…`; Shorts и прямые эфиры в первой версии не поддержаны.
- Скрипт сначала проверяет встроенную текстовую дорожку и реальные запросы
  субтитров работающего плеера, затем пробует прямую загрузку. Адрес работающего
  плеера сохраняется без изменения его параметров; запрос выполняется из страницы.
  Это экспериментальный способ, его работу на настоящем iPhone нужно проверить.
  Если `timedtext` пустой: используй открытую расшифровку, как описано выше.
  В диагностике есть источник субтитров, число строк расшифровки, число запросов
  плеера и результаты чтения: HTTP-статус, длина ответа, число фраз или категория
  ошибки. URL, токены, содержимое субтитров и ключ в диагностику не включаются.
  Также доступен импорт своего SRT/VTT.
- Ролики без субтитров не транскрибируются; DRM и закрытые видео не обходятся.
- Для первого теста используй встроенный в страницу плеер. Системный полный экран,
  PiP, блокировка экрана и фоновая работа Safari не проверены. Скрытие вкладки
  ставит видео на паузу. После возврата нажми «Продолжить».
- Если следующий блок не готов, видео ставится на паузу; продолжение требует нажатия.
- Речь растягивается по длительности блока. Большое ускорение и изменение высоты
  голоса возможны: первая версия не делает профессиональное выравнивание дубляжа.
- Оригинал выключается через `muted`, а не регулятор громкости, который на iOS ограничен.
  При остановке исходное состояние `muted` восстанавливается.
- На устройстве хранятся только явно сохранённый ключ и настройки. Переводы и звук —
  в памяти текущей сессии; после остановки очищаются. Исходный текст и перевод
  отправляются непосредственно в Google. Своего сервера и аналитики нет.

## Проверки разработчика

```sh
node --check userscripts/youtube-gemini-voice.user.js
node userscripts/tests/browser.mjs
```

Для браузерной проверки нужен Playwright и Chromium. Можно указать
`CHROMIUM_PATH=/usr/bin/chromium`; ключ API для теста не требуется.
